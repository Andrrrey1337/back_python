# Вариант 20 — Этап 2. Удалённый вызов процедур на основе TCP

Прототип веб-приложения со службой удалённого вызова процедур (RPC)
по протоколу TCP. Хранение данных выполняется в оперативной памяти.

## 1. Общее описание

Система состоит из следующих компонентов в каталоге `src/`:
- `model.py` — слой доступа к данным в оперативной памяти.
- `repl.py` — интерактивная консоль REPL (1 этап).
- `protocol.py` — упаковка/распаковка двоичных заголовков пакетов и XML-тел.
- `rpc_server.py` — TCP-сервер с журналированием запросов в `stdout`.
- `rpc_client.py` — класс клиента RPC с 10 методами, совпадающими с DAL.
- `demo_client.py` — демонстрация вызова всех 10 процедур.

Спецификация протокола (Таблица 20, порядок байт: little-endian):
- Запрос: Версия (1 байт, смещение 0), Код операции (1 байт, смещение 1),
  Размер тела (3 байта, смещение 2), Тело XML (смещение 5).
- Ответ: Код операции (2 байта, смещение 0), Размер тела (5 байт,
  смещение 2), Тело XML (смещение 7).

## 2. Описание всех функций и настроек

Настройки подключения (`src/protocol.py`):
- `DEFAULT_HOST = "127.0.0.1"` — адрес хоста.
- `DEFAULT_PORT = 9020` — порт TCP сервера.

Методы клиента RPC (`RPCClient` в `src/rpc_client.py`):
1. `create_person(identifier, ip, platform)` — добавление Person.
2. `get_persons()` — чтение всех записей Person.
3. `get_person(identifier)` — чтение Person по id.
4. `create_instruction(identifier, content, person, description, stage, spawned)` — создание Instruction.
5. `get_instructions()` — чтение всех записей Instruction.
6. `get_instruction(identifier)` — чтение Instruction по id.
7. `create_answer(identifier, output, stage, exception, instruction, cache_hit)` — создание Answer.
8. `get_answers()` — чтение всех записей Answer.
9. `get_answer(identifier)` — чтение Answer по id.
10. `get_recent_answers()` — реляционная выборка за последние 8 минут.

Сетевые методы:
- `connect()` — открытие соединения с сервером.
- `close()` — закрытие сокета.
